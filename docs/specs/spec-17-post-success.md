# 發布成功 功能規格書

**版本：** v1.0
**日期：** 2026-03-17
**狀態：** 已完成

---

## 1. 背景與目標

司機完成行程表單後，需要一個明確的成功回饋畫面，確認行程已發布並顯示摘要，降低使用者的不安全感，並引導下一步動作。

### 目標
1. 以動畫明確告知發布成功
2. 顯示行程摘要讓司機確認資訊正確
3. 引導司機前往「我的行程」管理已發布行程

---

## 2. 使用者故事

- 身為**剛發布行程的司機**，我希望看到清楚的成功畫面與行程摘要，這樣才能確認發布內容正確
- 身為**司機**，我希望成功頁有快速跳轉到「我的行程」的按鈕，這樣才能馬上管理發布的行程

---

## 3. 功能範圍

### 已完成功能
- 進場動畫：大圓形打勾圖示（scale + opacity，延遲 100ms 觸發）
- 標題「行程發布成功！」+ 副標「系統正在為你媒合順路乘客」
- 行程摘要卡：起點、終點（線段節點樣式）、出發時間、可載人數、每人費用
- 通知提示卡（emerald → teal）：「乘客預訂時將即時通知你」
- 「查看我的行程」主按鈕（→ `/trips`）
- 「返回首頁」次要按鈕（→ `/`）
- 使用 `<Suspense>` 包裹（因使用 `useSearchParams` 讀取 URL 參數）

### 待製作
- 無（發布成功頁功能完整）

---

## 4. 使用流程

1. 司機在 `/post` 完成兩步驟表單 → 點擊「發布行程」
2. 系統帶著 `?from=&to=&time=&seats=&price=` 導向 `/post/success`
3. 進場動畫播放（延遲 100ms）
4. 使用者查看行程摘要
5. 點擊「查看我的行程」→ `/trips`，或「返回首頁」→ `/`

---

## 5. 畫面與功能說明

**路由：** `/post/success?from={起點}&to={終點}&time={時間}&seats={人數}&price={費用}`
**需要登入：** 否（由 `/post` 的 AuthGuard 保護上游）

**進場動畫區塊**（頂部置中）
- 綠色漸層圓形（`w-24 h-24`）+ 打勾圖示（白色）
- 動畫：初始 `scale-50 opacity-0` → 100ms 後 `scale-100 opacity-100`（duration 700ms）
- 打勾圖示額外 delay 300ms

**文字區**（delay 200ms）
- 「行程發布成功！」大標
- 「系統正在為你媒合順路乘客」副標

**行程摘要卡**（白色圓角卡，delay 300ms）
- 起訖點（節點線段樣式：空心圓 → 連線 → 實心圓）
- 右側顯示出發時間
- 下方兩格：可載人數 / 每人費用

**通知提示卡**（emerald → teal，delay 400ms）
- 鈴鐺圖示 + 「通知已開啟・乘客預訂時將即時通知你」

**按鈕區**（delay 500ms）
- 「查看我的行程」（綠色主按鈕，→ `/trips`）
- 「返回首頁」（白色次要按鈕，→ `/`）

---

## 6. 資料說明

| 參數 | 來源 | 說明 |
|------|------|------|
| `from` | URL query | 起點（`/post` 表單傳入） |
| `to` | URL query | 終點 |
| `time` | URL query | 出發時間 |
| `seats` | URL query | 可載人數，預設 `"2"` |
| `price` | URL query | 每人費用，預設 `"0"` |

資料不寫入 localStorage，頁面刷新後 URL 消失則顯示預設值。

---

## 7. 設計規範

- 頁面背景：`bg-gradient-to-b from-green-50 to-gray-50`
- 成功圓形：`bg-gradient-to-br from-green-500 to-emerald-400`，`w-24 h-24`
- 動畫：`transition-all duration-700`，各元素有 `delay-200` ～ `delay-500`
- 通知卡：`bg-gradient-to-r from-emerald-500 to-teal-500`
- 摘要卡：`bg-white rounded-2xl shadow-sm border border-gray-100`
