# 預訂成功 功能規格書

**版本：** v1.0
**日期：** 2026-03-17
**狀態：** 已確認

---

## 1. 背景與目標

付款完成後，乘客需要一個明確的成功回饋，確認預訂已生效。同時藉此機會強化 ESG 減碳成就感，並引導使用者前往「我的行程」追蹤後續。

**目標：**
- 給予乘客清楚的付款成功視覺回饋，降低「有沒有成功？」的疑慮
- 顯示訂單編號與行程摘要，便於截圖留存
- 透過 CO₂ 貢獻動畫強化環保正向體驗

---

## 2. 使用者故事

- 身為**乘客**，我希望付款後看到明確的成功畫面，這樣才能確認預訂已完成。
- 身為**乘客**，我希望看到訂單編號，這樣才能在有疑問時對司機或客服對號。
- 身為**企業員工**，我希望看到這趟共乘實際減少了多少 CO₂，這樣才能感受到環保貢獻。
- 身為**乘客**，我希望可以直接跳到「我的行程」查看，這樣才能隨時掌握出發資訊。

---

## 3. 功能範圍

### 已完成功能
- 入場動畫：綠色勾勾圓圈（scale + opacity，delay 分層）
- 「預訂成功！」標題 + 「已通知 {司機名稱} 您的預訂」副標
- 訂單編號卡片（`JC` + 6 位隨機數字）
- 行程摘要卡（出發地 / 目的地 / 時間 / 司機姓名 / 費用）
- ESG 貢獻卡（CO₂ 減少量 + 進度條動畫 + 本月個人累計）
- 操作按鈕：「查看我的行程」（→ `/trips`）、「返回首頁」（→ `/`）

### 待製作
- 無（目前功能已完整呈現核心成功流程）

## 4. 使用流程

**唯一路徑（從確認付款頁自動跳轉）：**
1. 確認付款頁執行 `deductBalance()` 成功後，自動跳轉至 `/booking/success`
2. URL 帶入：`rideId`, `driverName`, `from`, `to`, `time`, `co2`, `price`
3. 頁面載入 100ms 後觸發動畫（`show = true`）
4. 動畫依序出現：勾勾圓圈 → 標題 → 訂單編號 → 行程摘要 → ESG 卡 → 按鈕
5. 乘客選擇「查看我的行程」或「返回首頁」

**注意：** 此頁面不驗證登入狀態，直接依 URL 參數顯示資訊。若直接輸入網址進入，顯示內容會以 URL 參數為準（空值則顯示預設文字）。

## 5. 畫面與功能說明

### 預訂成功頁
- **路由：** `/booking/success?rideId=&driverName=&from=&to=&time=&co2=&price=`
- **是否需要登入：** 否
- **背景：** `bg-gradient-to-b from-green-50 to-gray-50`
- **畫面元素（由上至下）：**
  1. **成功動畫區**：
     - 綠色漸層圓圈（w-24 h-24）+ 白色勾勾，`scale-50→scale-100`（700ms）
     - 「預訂成功！」+ 「已通知 {driverName} 您的預訂」，`opacity-0 translate-y-4 → 正常`（delay 200ms）
     - 訂單編號白色小卡，`JC` + 6 位數，綠色粗體（delay 300ms）
  2. **行程摘要卡**（delay 400ms）：
     - 出發地 + 出發時間 / 目的地（直線圖示）
     - 2 格資訊：司機姓名、費用
  3. **ESG 貢獻卡**（delay 500ms）：
     - 綠色漸層底，顯示 `{co2} kg CO₂ 減少排放`
     - 白色進度條：`width = min(co2 × 30, 90)%`，動畫 1000ms delay 700ms
     - 本月個人累計：`co2 × 3` kg CO₂（假資料）
  4. **操作按鈕**（delay 600ms）：
     - 「查看我的行程」— 綠色漸層主按鈕
     - 「返回首頁」— 白底灰字次要按鈕

---

## 6. 資料說明

- **資料來源**：全部來自 URL query 參數（由 `/booking/confirm` 跳轉時帶入）
- **訂單編號**：前端隨機產生，`"JC" + Math.floor(100000 + Math.random() * 900000)`，屬假資料
- **本月 CO₂ 累計**：`parseFloat(co2) × 3`，粗略估算，屬假資料
- 無任何新資料寫入 localStorage 或 sessionStorage

---

## 7. 設計規範

- 手機優先，最寬 448px
- 動畫統一用 CSS transition（`opacity` + `translate-y` + `scale`），不用 JS 動畫庫
- 各區塊 delay 間隔 100ms，依序呈現，避免一次全部跳出
- ESG 進度條額外延遲至 delay 700ms，讓視覺重心最後落在環保數字上
- 頁面使用 `<Suspense>` 包裹（因使用 `useSearchParams`）

---

## 8. 備註

- 訂單編號為前端隨機產生，重整頁面會換號，正式上線需由後端產生並持久化
- 本月累計 CO₂（`co2 × 3`）為假計算，正式應從使用者帳戶累計紀錄取得
- ESG 進度條的 90% 上限為視覺保護，避免進度條跑滿後看起來像「完成了就不用再努力」
