# 行程詳情 功能規格書

**版本：** v1.0
**日期：** 2026-03-17
**狀態：** 已確認

---

## 1. 背景與目標

使用者在搜尋結果頁看到感興趣的行程後，需要一個完整的詳情頁來確認所有資訊（司機、路線、集合地點、費用等），再決定是否預訂。

**目標：**
- 讓使用者在預訂前能看齊所有必要資訊，降低「訂錯了才發現」的狀況
- 透過 ESG 減碳卡強化選擇共乘的動機

---

## 2. 使用者故事

- 身為**準備預訂的乘客**，我希望看到完整的集合地點和備註，這樣才能確認我能準時抵達。
- 身為**在意費用的乘客**，我希望在詳情頁清楚看到每人費用，這樣才能確認預算再按下預訂。
- 身為**有環保意識的上班族**，我希望看到這趟共乘能減少多少碳排放，這樣才能感受到實際貢獻。

---

## 3. 功能範圍

### 已完成功能
- 綠色漸層 Header，顯示司機頭像、姓名、公司、星等評分、共乘次數
- 路線卡片：出發地、目的地、出發時間、車程時長、完整日期
- ESG 減碳卡：顯示預估減碳量（kg CO₂）及換算植樹棵數
- 行程資訊列：集合地點、車型車色、剩餘 / 總座位數、備註
- 底部預訂列：每人費用 + 「立即預訂」按鈕，點擊跳轉至 `/booking/confirm?rideId=...&seats=1`
- 找不到行程時顯示錯誤狀態，並提供「返回列表」連結
- 左上角「← 返回列表」連結

### 待製作
- 座位數選擇（目前固定帶入 1 人）
- 司機詳細評價列表
- 分享行程功能

---

## 4. 使用流程

**成功路徑：**
1. 使用者從 `/results` 點擊行程卡片，進入 `/results/[id]`
2. 頁面顯示該行程的完整資訊
3. 使用者確認集合地點、費用後，點擊「立即預訂」
4. 跳轉至 `/booking/confirm?rideId=ride-xxx&seats=1`

**例外情況：**
- 網址中的 id 不存在 → 顯示「找不到此行程」+ 「返回列表」連結

---

## 5. 畫面與功能說明

**路由：** `/results/[id]`
**是否需要登入：** 否（點「立即預訂」後若未登入，由 `/booking/confirm` 頁面的 AuthGuard 處理）

### Header 區塊
- 綠色漸層背景
- 左上角「← 返回列表」（連結至 `/results`）
- 司機頭像（姓氏文字，白色半透明圓角方塊）
- 司機姓名（白色大字）、所屬公司（白色半透明小字）
- 星等評分（黃色星星 + 數字）、共乘次數

### 路線卡片（白色圓角卡片，-mt-4 疊在 Header 上）
- 出發地（粗體）+ 出發時間（綠色標籤）
- 目的地 + 車程時長
- 完整日期（年月日星期）

### ESG 減碳卡
- 翠綠漸層背景
- 地球圖示
- 「這趟共乘預估可減少 X kg CO₂」
- 換算植樹棵數（「相當於種下 0.X 棵樹」）

### 行程資訊列（白色圓角卡片）
每列含綠色圖示 + 標籤 + 內容：

| 項目 | 內容來源 |
|------|----------|
| 集合地點 | `ride.meetingPoint` |
| 車輛 | `ride.carModel` |
| 剩餘座位 | `ride.availableSeats / ride.totalSeats 座` |
| 備註 | `ride.notes` |

### 底部預訂列
- 左側：「費用」標籤 + `NT$X / 人`（大字）
- 右側：「立即預訂」按鈕（綠色漸層，全寬）
- 點擊後跳轉 `/booking/confirm?rideId=...&seats=1`

### 錯誤狀態（id 不存在）
- 「找不到此行程」灰色文字
- 「返回列表」綠色連結

---

## 6. 資料說明

- **行程資料**：透過 `getRideById(id)` 從 `mockData.ts` 取得單筆行程
- **植樹換算公式**：`0.${Math.round(ride.co2Saved * 8)} 棵樹`（寫死在頁面內的計算邏輯）
- **無 localStorage 使用**

---

## 7. 設計規範

- 手機優先設計，最寬 448px
- 路線卡片以 `-mt-4` 疊在 Header 上，視覺上連貫不跳動
- 底部預訂列使用 `mb-6`，避免被 BottomNav 遮住

---

## 8. 備註

- 植樹換算數字（`0.X 棵樹`）目前為估算公式，後續確認正確換算係數後需更新
- ESG 減碳數字來自 `mockData.ts` 的 `co2Saved` 欄位，後續需改為真實計算值
